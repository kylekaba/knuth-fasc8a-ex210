# Review guide

A reviewer can approach the branch in four passes:

1. Read the project-level claims in [README.md](../README.md) and the sharper
   trust-boundary description in [LEAN.md](../LEAN.md).
2. Review the reusable soundness layer in
   [`CertificatePadeSoundness.lean`](../KnuthFasc8aEx210/CertificatePadeSoundness.lean),
   [`CertificateMatrixSoundness.lean`](../KnuthFasc8aEx210/CertificateMatrixSoundness.lean),
   and [`RankCheckpointSoundness.lean`](../KnuthFasc8aEx210/RankCheckpointSoundness.lean).
3. Sample an embedded data module, one bounded segment, and its composition
   chain—for example the `EmbeddedU1PlusRank*` modules.
4. Run `lake build`, `make rank-checkpoint-verify`, and `make hashes` to confirm
   kernel replay, deterministic artifact regeneration, and manifest integrity.

Large generated byte literals and repetitive segment declarations should be
reviewed structurally and via regeneration. The highest-value human review is
the generic implication from counters to mathematical statements and the final
composition of those statements.
